# cases/ — מקור האמת לתוכן לפי סוג נזק

`cases.json` הוא הקובץ היחיד שממנו נקראים שם הנזק, ההוק, שאלות העוזר ותוכן המסמך.
שלושה מקומות באתר קוראים ממנו:

| איפה | מה מוצג |
|---|---|
| הבניין בעמוד הראשי | `short` (התווית), צבע המשפחה |
| הבועה שנפתחת בלחיצה | `label`, `hook` |
| העוזר (`/assistant/`) | `states` (שאלה 1), `asked` (שאלה 2), `doc` (המסמך), `safety`, `guide` |

## קישור ישיר לכל נזק

```
https://taviv.co.il/assistant/?case=<id>
https://taviv.co.il/assistant/?case=<id>&state=<stage>
```

המזהים: `roof` `fire` `pipes` `structural` `neighbor` `burglary` `business` `shared` `unsure`.
`state` הוא השלב הכללי מהעמוד הראשי: `now` `checked` `returned` `dispute`. אם לנזק יש מצב אחד
שמתאים לשלב הזה, העוזר מדלג על שאלה 1; אחרת הוא שואל.
פרמטרי UTM שמצורפים לקישור נשמרים לאורך המסלול.

## מבנה רשומה

```json

  "icon": "fire",                     // שם אייקון מתוך assets/js/taviv-icons.js
  "intake": "FIRE",                   // סוג הנזק כפי שנשמר בליד (כמו בטופס /check/)
  "label": "שריפה",                   // השם המלא
  "short": "שריפה",                   // התווית על הבניין: עד 12 תווים; בצד ימין של הבניין עד 6
  "hook": "הפיח מגיע רחוק יותר מהאש.",        // עד 8 מילים, בלי מקף
  "safety": "…",                      // רשות. תמיד גלוי, גם לפני השארת פרטים
  "states": [                         // שאלה 1: "מה המצב עכשיו?" 3 עד 4 תשובות שמתאימות לנזק הזה
    { "id": "fresh", "stage": "now", "icon": "clock", "intake": "RECENT_DAMAGE",
      "label": "זה קרה בימים האחרונים",
      "next": "…",                    // "הצעד הבא" במסמך. תמיד גלוי
      "ruling": "TAV-002" }           // רשות: פסק דין אחר למצב הזה
  ],
  "asked": [                          // שאלה 2: "מה כבר נעשה?" עובדות לסימון, לא הוראות
    { "id": "photos", "icon": "camera", "q": "צילמנו לפני שנגענו",
      "miss": "…" },                  // מה שמופיע ב"עוד חסר בתיעוד" כשלא סומן (חלק נעול)
    { "id": "cleaned", "icon": "alert", "risk": true, "q": "כבר ניקינו או זרקנו דברים",
      "flag": "…" }                   // אזהרה שמופיעה כשסומן. תמיד גלויה
  ],
  "doc": {                            // החלק שנפתח אחרי השארת פרטים
    "stuck": "כותרת קצרה. הסבר.",     // "איפה מקרים כאלה נתקעים": המשפט הראשון הוא הכותרת
    "ruling": "TAV-013",              // מפתח מתוך rulings
    "appraiser": ["…", "…", "…"]      // "מה בודק שמאי רכוש מטעמכם": בדיוק 3
  },
  "guide": { "url": "/guides/…/", "title": "…" }    // רשות
```

## פסיקה (`rulings`)

המפתחות הם מזהי הכרטיסים מתיקיית "פסיקה וידע מקצועי" בדרייב (`TAV-0xx`).
לכל רשומה: `court`, `year`, `number`, `level` (רמת המקור בכרטיס: A עד D), `story`, `differs`, `ask`.

- **`verified: false` לא מוצג באתר החי.** העוזר מציג פסק דין רק אחרי ש־`verified` הוא `true`.
  בדמו הוא מוצג עם התווית "טיוטה לאימות".
- מסמנים `verified: true` רק אחרי בדיקה מול הנוסח המלא, כולל ערעור או דיון נוסף.
- בלי שמות של בעלי דין פרטיים, בלי סכומים, בלי שם עיר. ערכאה, שנה ומספר הליך בלבד.
- `story` מתאר רק מה שכתוב בכרטיס. `differs` אומר במה המקרה שונה. `ask` היא שאלת הבירור.

## מה נשמר כשמשאירים פרטים

העוזר שולח לאותה נקודת קצה של טופס `/check/` (אותו מבנה רשומה): שם, טלפון, `damage_type`,
`case_state`, ותקציר ב־`short_description` שמתחיל ב־`[העוזר]`. `cta_location` הוא `assistant_document`.

## כללים

- לשון רבים, בלי מחירים, בלי הבטחת תוצאה, בלי דחיפות מלאכותית.
- שורת בטיחות, "הצעד הבא" ואזהרות (`flag`) אף פעם לא ננעלים.
- `status: "draft"` בראש הקובץ נשאר עד שעידו מאשר את הניסוחים המקצועיים.
- מיקום הדירות על התמונה (קואורדינטות) נמצא ב־`assets/js/hero-building.js`, כי הוא שייך לתמונה ולא לתוכן.
- אחרי שינוי: להעלות את `version`, ולעדכן את הפרמטר `?v=` בקישורי ה־CSS/JS אם השתנו גם הם.
